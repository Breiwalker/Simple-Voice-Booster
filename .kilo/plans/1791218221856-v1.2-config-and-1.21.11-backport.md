# Simple Voice Booster 1.2 — Config overhaul + MC 1.21.11 backport

## Goal

Ship **mod version 1.2** with two changes:

1. A **mod-owned config** (JSON file + custom vanilla config screen) that lets users set the max boost and control the aggressive AGC/clipping overrides, replacing today's hardcoded 5000% / always-override behavior.
2. A **second build for Minecraft 1.21.11**, released alongside the existing 26.3 build.

Everything stays client-side. No server-side work.

## Baseline (current v1.1)

- Target: MC `26.3` (unobfuscated), Loom plugin `net.fabricmc.fabric-loom:1.18.2`, Java 25, loader `0.19.5`, Fabric API `0.161.0+26.3`.
- Simple Voice Chat `2.6.24` (Modrinth version id `OLnMVWXy`), API `2.6.24`, Mod Menu `21.0.0` (optional).
- Hardcoded `MicBoost.MAX_AMPLIFICATION = 50.0` (5000%). AGC is force-disabled; volume guard is fully `@Overwrite`-n.
- No README, no CHANGELOG, no git tags, no CI.

## Locked decisions

- **Config storage:** `config/simple_voice_booster.json` via Gson (already available through Minecraft/Fabric). No new runtime dependencies.
- **Config UI:** custom vanilla `Screen` reached from Mod Menu's "Configure" button.
- **Config options (exactly three):**
  - `maxBoostPercent` — int, default `5000`, valid range `100`–`20000`.
  - `forceManualGain` — bool, default `true` (true = disable AGC + force manual gain, matching 1.1).
  - `hardClip` — bool, default `true` (true = apply gain unconditionally and hard-clip; false = restore SVC's anti-clip guard).
- **Absolute ceiling:** the SVC config bound is widened to a fixed `20000%` (200x ≈ `46.0206 dB`). The user's `maxBoostPercent` is enforced dynamically in the slider span, the typed box, and the gain path, so the SVC config-entry API never needs runtime mutation.
- **Backport target:** exactly MC `1.21.11` via a **separate branch** (not a multi-version preprocessor). MC versions below 1.21.11 are out of scope.
- **Release:** one `1.2` release containing two jars (26.3 + 1.21.11).

## Architecture notes

- `MicBoost` (main source set) becomes config-aware and exposes: `absoluteMaxPercent()`, `absoluteMaxGainDb()`, `maxBoostPercent()`, `maxAmplification()`, `maxGainDb()`, plus the existing `gainDbToPercent` / `percentToGainDb`. Config must be loaded before any SVC class initializes, so load it in `Simple_voice_booster.onInitialize()`.
- The SVC config entry (`ClientConfig.<init>` constant `24.0`) is patched to the **absolute** ceiling `MicBoost.absoluteMaxGainDb()`.
- The slider's folded span constant `64.0` is patched to `MicBoost.maxGainDb() - VolumeManager.MIN_GAIN` (dynamic, respects the user's max).
- Main source set is visible to the client source set in the split-source-set layout, so client mixins can read the config holder.

## Validation

Build/run on **both** branches (`./gradlew build` then `./gradlew runClient`); watch the log for `InvalidInjectionException` / `InjectionError`.

Manual smoke test (repeat on 26.3 and 1.21.11):

- Slider spans exactly to the configured `maxBoostPercent`; typed box syncs both ways and clamps out-of-range values.
- Tooltip swaps to "Boosted with Simple Voice Booster" at ≥ 200%.
- `forceManualGain = true`: AGC option hidden and manual gain applied. `false`: AGC option visible and functional.
- `hardClip = true`: loud input clips as expected. `false`: SVC's anti-clip guard behaves as vanilla.
- Config persists across restarts; a corrupt/missing JSON falls back to defaults without crashing; a hand-edited SVC mic gain cannot exceed the 20000% ceiling.
- Mod Menu "Configure" opens the new screen; the mod still loads and works when Mod Menu is absent.
- Changing `maxBoostPercent` and reopening SVC settings shows the new span.

## Risks / failure modes

- Converting `VolumeManagerMixin` from `@Overwrite` to a cancellable `@Inject` must preserve the current output; verify no guard is applied twice when `hardClip` is true.
- Dynamic slider span means a previously stored SVC gain may map to an unexpected slider position after the max changes; reopening the settings screen re-syncs.
- SVC internals/constants can differ between the 2.6.24 (26.3) build and the 1.21.11 build — this is the main reason for a branch, and each target needs its own target verification (step 19).
- `required: true` mixins hard-fail on incompatible SVC versions; keep the `fabric.mod.json` SVC `depends` value accurate per branch.
- No CI today; without step 23 the two branches must be built and published manually.

## Out of scope for 1.2

- MC versions below 1.21.11.
- A multi-version/Stonecutter single-tree build.
- Server-side or protocol behavior.

Implementation requires source edits in both branches; switch to an implementation-capable agent to execute this plan.
